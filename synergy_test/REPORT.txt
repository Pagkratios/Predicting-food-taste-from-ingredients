====================================================================================================
DOES AN EXPLICIT UMAMI-SYNERGY INTERACTION TERM IMPROVE THE HYBRID MODEL?
====================================================================================================


Question under test. A reviewer objected that the hybrid model cannot represent nucleotide–glutamate
synergy (IMP/GMP × free glutamate), which is multiplicative, because every current feature enters
additively. This report tests empirically whether adding a single product feature phi_syn =
f_nucleotide × f_glutamate fixes that.

Verdict up front: it does not. Adding phi_syn makes umami LOOCV MAE worse by +0.064 points on the
0–100 scale (5.746 → 5.810). Lasso zeroes the coefficient on the full-data fit and in 96% of LOOCV
folds. Even an unregularised, in-sample, no-CV oracle fit — the most generous possible test — gains
only 0.004 MAE points (partial F p = 0.66). The dataset contains 18/70 recipes in which both classes
are co-present, and the smallest synergy effect this design could detect is an ~11-point umami
shift. The correct conclusion is not "there is no synergy" but "this dataset cannot see it, and a
product feature does not help." Full numbers in §6–§7; verdict and what would settle it in §8; what
I could not do in §9.

1.4 A note on the dataset size claim
------------------------------------


The manuscript abstract says "70 recipes decomposed into 209 ingredient-level taste references". The
dataset at data/raw_recipes.py has 70 recipes, 115 unique ingredient names, and 510 ingredient
instances across recipes. 115 matches the manuscript's later statement ("115 per-ingredient
features") and matches the repo's Lasso per-ingr model. I could not reproduce 209 from this file
under any counting rule I tried (unique names = 115, instances = 510, unique name × taste pairs =
575). The task brief also said 209. I used the 115 actual unique ingredients; the full list with
per-recipe mass fractions is in results/ingredient_inventory.csv and
results/recipe_ingredient_mass_fractions.csv. This discrepancy is flagged, not resolved — see §7.

objection.


2.2 The Lasso + LOOCV loop, and alpha selection
-----------------------------------------------


loo_evaluate(), lines 137–148 of hybrid_analysis.py:

    loo = LeaveOneOut()                         # 70 folds
    for tri, tei in loo.split(X):
        sc = StandardScaler()
        Xtr = sc.fit_transform(X[tri])          # standardisation fit on TRAIN fold only
        Xte = sc.transform(X[tei])
        m = LassoCV(alphas=alphas, cv=5, max_iter=20000)   # alphas = np.logspace(-3,1,30)
        m.fit(Xtr, y[tri])
        preds[tei] = m.predict(Xte)

Alpha is not fixed. LassoCV performs an inner 5-fold CV over a 30-point log grid 10^-3 … 10^1 inside
each of the 70 outer LOOCV folds, so alpha is re-selected 70 times. The single alpha printed in the
repo's Table S3 (hybrid_analysis.py lines 292–307) comes from a separate full-data fit used only for
reporting coefficients, not for the CV metrics.

The hybrid feature set is assembled at line 196: [f'{t}_hs_mid', f'{t}_voigt'] + chem_cols → 10
features per taste.

2.4 How the existing keyword categories are defined
---------------------------------------------------


They are regex substring matches on the raw ingredient-name string, case-insensitive, with no
vocabulary or ontology behind them (hybrid_analysis.py lines 33–38, applied by frac_match, lines
42–47). Consequences worth knowing:

- allium and fermented overlap heavily with each other and with protein: every cheese is both
  protein_frac and fermented_frac; "Spices/onion" counts as allium.
- ^salt$ is anchored, so "Peanuts salted" does not count as salt.
- ^water matches "Water" and also "Water chestnut" — a false positive that inflates water_frac (and
  hence conc_factor) for any recipe containing water chestnut. I did not fix this; it is pre-existing
  repo behaviour and fixing it would change the baseline I am comparing against. Flagged in §9.

5. Step 3 — Residual diagnostic
====================================================================================================


results/step3_residual_diagnostic.csv, results/step3_residual_diagnostic_other_vars.csv. Figure:
figures/fig2_residual_vs_phisyn.png.

Umami LOOCV residual (actual − predicted, current 10-feature hybrid) regressed on phi_syn:


subset           n   OLS slope  SE      p      R²      Spearman ρ  Spearman p
-----------------------------------------------------------------------------
all recipes      70  −12.49     65.73   0.850  0.0005  +0.210      0.080
co-present only  18  −258.86    100.83  0.021  0.292   −0.494      0.037


Two things, and they point the same way:

1. Across all 70 recipes there is nothing. Slope p = 0.85, R² = 0.0005. The Spearman ρ = +0.21 (p =
   0.08) is not evidence for synergy — it is driven almost entirely by the 52 tied zeros versus the 18
   non-zeros, i.e. it says "recipes containing both meat and glutamate-rich items tend to be
   under-predicted", which is a statement about savoury dishes in general, not about the product.
   Consistent with this, the same Spearman ρ ≈ 0.21 appears for every monotone transform of phi_syn
   (sqrt, log1p, ×conc, ×conc², broad classes) — a rank statistic cannot distinguish them, so it
   carries no information about multiplicativity specifically.
2. Within the 18 co-present recipes the relationship is significantly NEGATIVE (slope −259, p = 0.021;
   ρ = −0.49, p = 0.037). Higher phi_syn → the current model over-predicts umami. This is the opposite
   sign to the synergy hypothesis. I do not claim this is a real anti-synergy effect: with n = 18 and
   44% of the phi_syn mass in 3 recipes, it is more plausibly the confound that f_nucleotide (and hence
   phi_syn) is 0.84-correlated with protein_frac, which the model already uses, so high-meat recipes
   are already handled and the residual there reflects something else. But it does mean the data give
   no support in the hypothesised direction.

- (b), (c), (e) look "retained" but are not evidence. The concentration-scaled and sqrt forms are kept

  not mechanistic: phi_syn is zero in 52 recipes and tiny (max 0.065) in the rest, so after
  within-fold standardisation the raw product is a near-degenerate spike that Lasso shrinks away,
  while multiplying by conc_factor² (range 1–10) or taking sqrt spreads it out enough to survive the
  penalty. Being selected and being useful are different things — (c) is retained in 100% of folds and
  still has worse MAE than baseline.
- (c) is the closest to a tie: ΔMAE +0.005 points (i.e. worse by half a hundredth of a point), with
  RMSE 0.016 better and PCC 0.001 better. This is noise, and §7's permutation test treats it as such.
- (f), the control, is the most informative row. Adding the two class fractions without any product is
  worse than adding the product (+0.144 vs +0.064) and worse than baseline. So the missing ingredient
  is not "a main effect the model lacked" either. Both classes are already substantially represented:
  f_nucleotide correlates r = 0.84 with the existing protein_frac and r = 0.64 with umami_voigt;
  f_glutamate correlates r = 0.43 with allium_frac. See §7.3.
- (g) — the textbook interaction specification (both main effects plus the product) — zeroes the
  product in 98.6% of folds while keeping both main effects. If a genuine interaction existed, this is
  the specification that would find it.
- (h) shows the verdict does not hinge on my ambiguous class assignments: swapping in the broad
  glutamate list (mozzarella, cream cheese, yoghurt, capers, olives, sambal, peanut sauce) changes MAE
  by 0.03 points and leaves the coefficient at exactly zero.

------------------------------------


phi_syn was shuffled across the 70 recipes 1000 times (seeded, default_rng(20260727)); for each
shuffle the full 11-feature LOOCV was refit and the MAE improvement (baseline MAE − variant MAE;
positive = the feature helps) recomputed.


variant               true improvement (points)  true improvement (%)  null mean ± SD    null [p5, p95]    true value's percentile in null  one-sided p
-------------------------------------------------------------------------------------------------------------------------------------------------------
a. + phi_syn          −0.0640                    −1.11%                −0.0965 ± 0.1172  [−0.295, +0.085]  63rd                             0.371
c. + phi_syn × conc²  −0.0049                    −0.09%                −0.0915 ± 0.1102  [−0.253, +0.086]  88th                             0.121


Read this carefully, because it is the cleanest statement of the null result:

- The true improvement is negative for both variants. There is no improvement to test for
  significance.
- The real phi_syn sits at the 63rd percentile of what a randomly shuffled phi_syn achieves. A random
  relabelling of which recipes are "synergistic" performs about as well as the chemically motivated
  one. Two-thirds of random shuffles do worse — but that is because any extra column typically costs a
  little MAE, not because the real one carries signal.
- Even the best-behaved variant (c) only reaches the 88th percentile, p = 0.121 — short of
  significance, and its "improvement" is still negative in absolute terms.
- Note the null distribution is centred at −0.097, not 0. Adding a random column costs about a tenth
  of an MAE point on average. That is the price of the extra parameter under this alpha grid, and it
  is the correct benchmark against which −0.064 should be judged.

8. Verdict
====================================================================================================


Does the interaction term help?
-------------------------------


No. It does nothing, and slightly hurts. Umami LOOCV MAE goes from 5.746 to 5.810, i.e. 0.064 points
worse on the 0–100 scale (−1.11%). Lasso assigns it a coefficient of exactly zero on the full-data
fit and in 96% of LOOCV folds. Under repeated 10-fold CV it is worse in 5/5 seeds. In a 1000-shuffle
permutation test the real feature sits at the 63rd percentile of the random-shuffle null (p = 0.371)
— a randomly relabelled phi_syn performs about as well. None of the five requested variants beats
the baseline; the best (phi_syn × conc²) is +0.005 MAE points worse. The main-effects-only control
(f) is worse still (+0.144), so this is not a case of a missing main effect masquerading as a
missing interaction either.

For absolute scale: the umami ground truth has mean 15.0 and SD 10.9, and the current model's MAE is
5.75 points. The largest effect any variant produces in any direction is 0.15 points, against a
seed-to-seed CV noise floor of ±0.27 points.


Is it identifiable given n?
---------------------------


No, and this is the more important answer. Three independent facts say so:

1. 18 of 70 recipes have both classes present. The other 52 carry zero information about the product.
   The top 3 recipes hold 44% of the total phi_syn mass.
2. The classes are already in the model. f_nucleotide is 88% linearly explained by the existing 10
   features (r = 0.84 with protein_frac alone). The "new" feature is largely a re-encoding of what
   protein_frac, umami_voigt and allium_frac already carry.
3. Minimum detectable effect ≈ 11 umami points at the most synergistic recipe in the dataset — about
   one full SD of the ground truth. Real IMP×Glu synergy in the literature is a large sensory effect
   but would have to be implausibly large at these mass fractions and this measurement precision to
   clear that bar.

So the finding is "this dataset cannot see it", not "synergy does not exist". Those are different
claims and the report should not be used to make the second one.


One thing the reviewer's framing gets wrong, worth saying in the response
-------------------------------------------------------------------------


The objection states that the model "cannot represent" multiplicative effects because every feature
is additive. That is not accurate: maillard_potential = protein_frac × sugar_frac is already a
product of two mass fractions, and it is one of the eight chemistry proxies. The architecture admits
products; the model is linear in features, not in ingredients. The accurate version of the objection
is narrower — this particular product was not among the eight — and this report answers that
narrower version directly: we added it, in six specifications, and it contributed nothing.


What would be needed to settle it
---------------------------------


In rough order of leverage:

1. Recipes designed for the contrast. A factorial set — nucleotide-only, glutamate-only, both, neither
   — at matched total savoury mass. Even 20–30 such recipes would beat 70 opportunistic ones, because
   the current design confounds phi_syn with "is this a meat dish" (r = 0.53 with protein_frac).
2. Actual measured concentrations, not name-keyed mass fractions. IMP/GMP and free glutamate in mg/100
   g, or at minimum a per-ingredient lookup from a food-composition database. The current proxy assumes
   every gram of "Minced beef raw" delivers the same IMP as every gram of "Cod boiled", and that mass
   fraction is proportional to concentration in the aqueous phase. Both are strong assumptions and
   neither is testable with this dataset.
3. Ingredients that isolate the mechanism. The dataset has no mushroom, no yeast extract, no bouillon,
   no fish sauce, no seaweed, no anchovy-as-such — precisely the ingredients where nucleotide and
   glutamate content are high and dissociable. One fish item exists, in one recipe.
4. A power calculation before the next round. Given the ~86-unit SE, resolving a synergy effect of,
   say, 3 umami points at max phi_syn would require roughly a 10–15× reduction in that SE — achievable
   mainly through (1) and (2), not through more recipes of the same opportunistic kind.


Suggested shape of the reviewer response
----------------------------------------


State that (a) the architecture already contains a multiplicative term, so the objection's premise
is too strong; (b) the specific IMP×Glu product was tested in six specifications plus a main-effects
control and a permutation test, and changed umami MAE by −0.06 points (worse), with the coefficient
zeroed in 96% of LOOCV folds; (c) the honest reason is that only 18/70 recipes are co-present and
the design's minimum detectable effect is ~11 umami points, so the study is underpowered for this
mechanism; and (d) name it as a limitation with the specific experiment that would settle it.
Reporting (c) and (d) is stronger than adding a feature that does nothing.

9. What I could not do, and why
====================================================================================================


1. Reconcile the "209 ingredients" claim. The dataset has 115 unique ingredient names and 510
   ingredient instances. I could not derive 209 under any counting rule I tried. The manuscript itself
   later says "115 per-ingredient features", so the abstract's 209 may be an error or may refer to a
   source table not in this repo. This should be checked before submission — it is in the abstract and
   in the Figure 1 caption. I did not change anything; I used the 115 that exist.
2. Test true nucleotide/glutamate concentrations. No compositional data exist in this repo — only
   per-ingredient sensory scores and mass fractions. Every class fraction here is a name-keyed mass
   proxy, which is the same level of rigour as the existing eight chemistry features but is a real
   limitation for a mechanism that is concentration- and ratio-dependent (the classic IMP:Glu synergy
   is strongly ratio-dependent, and mass fraction cannot express a ratio of concentrations).
3. Cover the spec's full class definitions. Shellfish, anchovy-as-such, mushroom, yeast extract,
   bouillon/stock cubes, fish sauce, seaweed and corn have no representative in this dataset. The
   classes tested are the intersection of the spec with what exists.
4. Fix a pre-existing bug I noticed. WATER_PAT = r'(?i)^water' also matches "Water chestnut", so any
   recipe containing water chestnut gets inflated water_frac and conc_factor. I deliberately left it
   alone — fixing it would change the baseline this whole comparison is against, and the brief said not
   to change pipeline logic. Flagging it as a separate item worth a look.
5. Resolve the Worcestershire dual-class assignment. It is legitimately both a fermented (glutamate)
   and an anchovy-containing (nucleotide) ingredient. I assigned it to glutamate only. Assigning it to
   both would let one ingredient generate phi_syn by itself, which is not what synergy means. I did not
   run a third sensitivity for it; given that the broad-class sensitivity (h) moved MAE by 0.03 points,
   it would not change anything.
6. Say anything useful about bitterness. Its ground truth is mean 1.57, SD 1.38, with 87% of values ≤ 3
   — a floor effect. Baseline PCC is −0.098. Its numbers are reported for completeness but are not
   interpretable, consistent with how the repo already excludes bitter from 4-D averages.
7. Establish that the negative within-co-present slope (§5) means anything. It is nominally significant
   (p = 0.021, Spearman p = 0.037) but it is a post-hoc subset of n = 18 with 44% of the leverage in 3
   recipes, and phi_syn is confounded with protein_frac (r = 0.53). I report it because it is the
   opposite of the hypothesised direction and the brief asked for honest reporting, but I would not put
   it in a manuscript as a finding.
